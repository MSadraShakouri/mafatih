## Future checks

```sh
npm run check:line-breaks           # also part of npm run check / CI
npm run check:line-breaks -- --list # show any retained breaks and their review states
npm --silent run check:line-breaks -- --json # machine-readable report
```

There are currently **zero** physical separators in the scanned current content and the exception list is empty. The guard scans active pooled item titles, tags, row fields (including excluded audio rows), English titles, source metadata and paragraphs, navigation titles, source display fields and source claims. It does not scan old values retained *only* in editorial history. It detects LF, CRLF, CR, NEL, Unicode line/paragraph separators, vertical tab and form feed. Soft visual wrapping is not a physical separator and is not flagged.

`data/line-break-exceptions.json` can pin each deliberately retained break to its stable location, current content-addressed text ID, separator kind and zero-based **Unicode code-point** offset. Entries require a meaningful reason and are normally `pending`. The check fails on newly introduced, removed, moved, differently encoded, duplicated or text-changed exceptions. Editing a field with an excepted break therefore requires rechecking it even if the break was not the intended edit. The guard also rejects pooled text edited in place without a new content ID.

To resolve a pending entry, inspect its surrounding row and neighboring source rows against appropriate evidence. Use the copy-on-write editing workflow; retain old IDs/values, record the occurrence and evidence, and respect reviewed alignment spans. Remove the exception if the break was removed, or explicitly update its exact current ID/offset/kind and reason if it must remain. If an intentional new break is required, add an explicit `pending` exception after inspecting it. A retained break can be marked `reviewed` **only after genuine human review**, by adding a `review` object with `reviewer`, real ISO `date`, and an `evidence` description identifying what was checked. The guard validates these fields but cannot verify their truth or certify a source/rights decision. Do not assume paragraph boundaries are accidental merely to make the check pass; assess the visual consequences, and never remove meaningful repetitions or invent translations. Further cross-row moves require an explicit reversible occurrence mapping and careful source review; they are not a general row-splitting or migration facility.
